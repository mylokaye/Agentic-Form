## JavaScript Feature Register

Feature IDs are stable behaviour identifiers, not release numbers or priorities. Do not renumber or reuse an existing ID. When adding or materially changing JavaScript behaviour, update its inline `F#` comment, this register, and the README when user-visible behaviour changes. Add or update regression coverage only when the user requests testing.

Use the inline format `// F# — Canonical feature name: intent or constraint.` Shared helpers may list multiple IDs only when they directly support each named feature. Generic DOM references, build packaging, and other infrastructure must be labelled as shared or infrastructure rather than assigned a misleading feature ID.

| ID | Canonical feature | Exact behaviour contract | Code ownership |
| --- | --- | --- | --- |
| F1 | Approximate-location prefill | On initial load, make one best-effort FreeIPAPI request with a 5-second timeout. Accept only a recognised ISO country code. Fill Country only if the visitor has not edited it, and fill the first valid international dialling prefix only while Phone number is empty. Fail silently in the UI and log generic `[F1]` technical outcomes without IP, location, or form data. | Browser code in `index.html`. |
| F2 | Country and State controls | Start Country empty, render recognised countries by English display name in alphabetical order, and keep the value as its ISO code. Show and enable State only when Country is `US`; otherwise hide and disable State so it is excluded from submission. | Browser code in `index.html`. |
| F3 | Browser-language prefill | On initial load, convert the base of `navigator.language` to an English language name through `Intl.DisplayNames`. Keep Language editable and leave it empty when the API, locale, or field is unavailable. Make no network request. | Browser code in `index.html`. |
| F4 | Progression validation | Stage 1 requires First name, Last name, and a valid-looking Email address. Failed Stage 1 fields receive the shared red invalid edge and matching `aria-invalid`; both clear when corrected. Stage 2 requires First name, Last name, Website, and Company name. Validation controls action readiness without a shared status message and does not claim identity or mailbox verification. | Browser code in `index.html`. |
| F5 | Email-domain suggestions | After Stage 1 Email validation succeeds, derive an HTTPS Website URL and Company name from the email domain. Track ownership of generated values: refresh a value when Email changes only while it remains untouched, and preserve it once the visitor edits it. Fill empty fields only and do not infer a person's name from their email address. | Browser code in `index.html`. |
| F6 | Four-stage navigation | Keep exactly one stage visible, update Back/Continue/Submit labels, and show a compact full-width solid-green progress bar at one-quarter, one-half, or three-quarters for Stages 1-3 with matching accessible progress semantics. Animate only the active stage with restrained entry motion, and animate progress width, unless reduced motion is requested. Hide the progress bar on the final feedback stage, move focus to the first meaningful control after navigation, and preserve entered values and newsletter choice while moving between stages. Back cannot interrupt active F7 enrichment. | Browser code in `index.html`. |
| F7 | Company and inquiry enrichment | Start after successful Stage 1 progression. Send only normalised `companyUrl` and optional `message` to the local or hosted `/enrich-company` adapter. Accept exactly five string fields: `industry`, `about`, `urgency`, `sentiment`, and `query`. Use request IDs, input snapshots, abort controllers, and timeouts so stale or failed requests never overwrite current state or block progression. Keep DeepSeek credentials server-side. | Browser code in `index.html`, local adapter in `dev-proxy.mjs`, and hosted adapter generated by `scripts/build-site.mjs`. |
| F8 | Local prototype submission | On Stage 3, accept one Submit Inquiry action, disable repeat submission, transition to the prototype-only Stage 4 feedback screen, and emit only a generic technical console message. Do not send a submission payload to a backend. | Browser code in `index.html`. |
| F9 | Debug-gated current URL capture | On initial load, set the read-only `currentUrl` field to `window.location.href`, including its query string and hash. Show the standalone Debug panel only when the URL includes `?debug`; do not log, persist, or transmit the value. | Browser code in `index.html`. |
| F10 | Personalized newsletter heading | On initial load and whenever First name changes, show `Content tailored for you, First name.` in the Newsletter banner. Use a generic no-name fallback when First name is empty; do not log, persist, or transmit the displayed name. | Browser code in `index.html`. |
| F11 | Conditional newsletter topics | Always show `New products & promotions` and `Shutdown and critical alerts` in the Newsletter banner. Show `Spare parts & service reminders` only when Inquiry subtype is `Spare parts`. Use Inter at 12px in `#230D39`; do not log, persist, or transmit the subtype. | Browser code in `index.html`. |
| F12 | AI company-summary tooltip | Show the AI explanation on hover and keyboard focus, and let click or tap toggle it. An outside click closes an explicitly opened tooltip. This only explains the company-summary experience and never reads, stores, or transmits form data. | Browser code in `index.html`. |
| F13 | Prototype feedback rating | Show a fourth-stage inquiry thank-you screen with five clickable star buttons and no GDPR notice or in-form Debug controls. Clicking any star hides the rating and smoothly reveals `Thank you for your feedback.` unless reduced motion is requested; do not record, store, transmit, or wire the rating to a backend. | Browser code in `index.html`. |
| F14 | Google Analytics form lifecycle events | Load GA4 with the existing measurement ID and send `form_view` once on load, `form_start` once on first form focus, `form_step_view` for visible stages, `form_step_complete` after successful stages 1-3, `form_validation_error` for failed progression in stages 1-2, `form_submit` once per submit attempt, and `form_submit_success` or `form_submit_error` for the local submission outcome. Send only fixed event names and step metadata; never send form fields, URLs, enrichment values, or ratings. | Browser code in `index.html`. |

F1 is reserved for the existing FreeIPAPI behaviour. Continue new JavaScript features with the next unused stable ID.
