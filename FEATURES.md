## JavaScript Feature Register

Feature IDs are stable behaviour identifiers, not release numbers or priorities. Do not renumber or reuse an existing ID. When adding or materially changing JavaScript behaviour, update its inline `F#` comment, this register, and the README when user-visible behaviour changes. Add or update regression coverage only when the user requests testing.

Use the inline format `// F# — Canonical feature name: intent or constraint.` Shared helpers may list multiple IDs only when they directly support each named feature. Generic DOM references, build packaging, and other infrastructure must be labelled as shared or infrastructure rather than assigned a misleading feature ID.

| ID | Canonical feature | Exact behaviour contract | Code ownership |
| --- | --- | --- | --- |
| F1 | Approximate-location prefill | On initial load, make one best-effort FreeIPAPI request with a 5-second timeout. Accept only a recognised ISO country code. Fill Country only if the visitor has not edited it, and fill the first valid international dialling prefix only while Phone number is empty. Fail silently in the UI and log generic `[F1]` technical outcomes without IP, location, or form data. | Browser code in `index.html`. |
| F2 | Country and State controls | Start Country empty, render recognised countries by English display name in alphabetical order, and keep the value as its ISO code. Show and enable State only when Country is `US`; otherwise hide and disable State so it is excluded from submission. | Browser code in `index.html`. |
| F3 | Browser-language prefill | On initial load, convert the base of `navigator.language` to an English language name through `Intl.DisplayNames`. Keep Language editable and leave it empty when the API, locale, or field is unavailable. Make no network request. | Browser code in `index.html`. |
| F4 | Progression validation | Stage 1 requires First name, Last name, and a valid-looking Email address. Failed Stage 1 fields receive the shared red invalid edge and matching `aria-invalid`; both clear when corrected. Stage 2 requires First name, Last name, Website, and Company name. Validation controls action readiness without a shared status message and does not claim identity or mailbox verification. | Browser code in `index.html`. |
| F5 | Email-domain suggestions | After Stage 1 Email validation succeeds, derive an HTTPS Website URL and Company name from the email domain. Track ownership of generated values: refresh a value when Email changes only while it remains untouched, and preserve it once the visitor edits it. Fill empty fields only and do not infer a person's name from their email address. | Browser code in `index.html`. |
| F6 | Two-step navigation | Keep exactly one form step visible. Step 1 uses Continue; Step 2 uses Back and Submit Inquiry. Show an accessible progress bar at one-half and full width for Steps 1 and 2, then hide it on the post-submit completion screen. Animate the active step and progress unless reduced motion is requested, move focus after navigation, and preserve entered values when moving back. | Browser code in `index.html`. |
| F7 | Retired company and inquiry enrichment | Retired. The form no longer sends company URLs or inquiry messages for enrichment or exposes enriched results. F15 separately sends only Inquiry text for category classification. Keep this stable ID reserved. | Retired; no active code ownership. |
| F8 | Local prototype submission | On Step 2, accept one Submit Inquiry action, disable repeat submission, transition to the post-submit feedback screen, and emit only a generic technical console message. Do not send a submission payload to a backend. | Browser code in `index.html`. |
| F9 | Debug-gated current URL capture | On initial load, set the read-only `currentUrl` field to `window.location.href`, including its query string and hash. Show the standalone Debug panel only when the URL includes `?debug`; do not log, persist, or transmit the value. | Browser code in `index.html`. |
| F10 | Retired personalized newsletter heading | Retired because newsletter subscription was removed. Keep this stable ID reserved. | Retired; no active code ownership. |
| F11 | Retired conditional newsletter topics | Retired because newsletter subscription was removed. Keep this stable ID reserved. | Retired; no active code ownership. |
| F12 | Retired AI company-summary tooltip | Retired with F7 because the company-summary experience was removed. Keep this stable ID reserved. | Retired; no active code ownership. |
| F13 | Post-submit feedback rating | After the local Step 2 submission, show the inquiry thank-you screen with five clickable star buttons, no progress bar, and no GDPR notice. Clicking any star smoothly reveals `Thank you for your feedback.` unless reduced motion is requested; do not record, store, transmit, or wire the rating to a backend. | Browser code in `index.html`. |
| F14 | Google Analytics form lifecycle events | Load GA4 with the existing measurement ID and send `form_view` once on load, `form_start` once on first form focus, `form_step_view` for the two visible form steps, `form_step_complete` after successful steps 1 and 2, `form_validation_error` for failed progression in steps 1 and 2, `form_submit` once per final submit attempt, and `form_submit_success` or `form_submit_error` for the local submission outcome. Send only fixed event names and step metadata; never send form fields, URLs, or ratings. | Browser code in `index.html`. |
| F15 | TypeSafe inquiry classification | On valid Step 1 Continue, send only non-empty Inquiry text to the same-origin `/api/classify-inquiry` route. TypeSafe returns one of New Business, Service, Parts, or Other; use its top Choice regardless of confidence and fill Inquiry type only if the visitor has not edited that field. Skip blank Inquiry. If the route fails or returns an invalid category, continue without changing the value and show an accessible status. Never log or persist the text, key, or response. | Browser code in `index.html`; local adapter in `dev-proxy.mjs`; hosted route in `scripts/build-site.mjs`. |

F1 is reserved for the existing FreeIPAPI behaviour. Continue new JavaScript features with the next unused stable ID.
